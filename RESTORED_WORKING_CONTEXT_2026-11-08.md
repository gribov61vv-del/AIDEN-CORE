# AIDEN / TRIAD — восстановление контекста и план интеграции

Дата: 2026-11-08. Документ фиксирует проверенные сведения и незавершённые задачи. Он не утверждает, что интеграция уже выполнена.

## Архитектура
- AIDEN — верхний уровень ассистента и координатор.
- WOV — маршрутизатор запросов и локальный шлюз.
- TRIAD — собственное локальное алгоритмическое ядро рассуждения; не LLaMA и не оболочка над готовой LLM.
- Symbiosis — связка компонентов и рабочих процессов.
- JARVIS — голосовой интерфейс (распознавание речи, озвучивание, команды).
- PIKACHU — самостоятельный локальный модуль, отдельный от TRIAD.
- TinyLlama — необязательный генератор формулировок, не источник истины и не обязательная зависимость TRIAD.

Не объединять компоненты в один неразличимый модуль и не удалять отдельные точки входа, память или проекты.

## Принцип TRIAD
Три этапа: (1) факт / источник / свидетельство; (2) расчёт / логика; (3) проверка / согласованность.
Ранее подтверждались SQLite-память, ограниченная безопасная арифметика, проверка размерностей, лексический поиск, обнаружение возможных конфликтов и журнал свидетельств. Лексический поиск не называть векторным. Модуль конфликтов не выносит автоматический вердикт об истине.

## Целевая схема
JARVIS (speech-to-text) → WOV /ask → TRIAD → ответ → JARVIS (text-to-speech).

PIKACHU подключается отдельно как самостоятельный модуль через 127.0.0.1:8001. Он не подменяет TRIAD и не должен занимать порт WOV.

Требования:
- TRIAD работает без обязательной LLM.
- JARVIS — интерфейс, не самостоятельный источник истины.
- PIKACHU имеет отдельные тесты и health status.
- Межсервисные вызовы имеют таймауты, request_id и обработку недоступности.
- Не запускать несколько копий PIKACHU на одном порту.
- Не открывать локальные API наружу без аутентификации.
- Не выполнять системные команды из распознанной речи без белого списка и подтверждения опасных действий.
