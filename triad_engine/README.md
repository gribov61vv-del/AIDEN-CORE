# TRIAD-local

Локальный лёгкий движок для AIDEN-CORE. Ядро работает на стандартной библиотеке Python; HTTP-обёртка использует Flask. Облачный API и API-ключ не нужны.

## Возможности

- Проверка размерностей физических выражений (`POST /dimensions`).
- Поиск возможных противоречий в памяти (`POST /conflicts`); эвристика, не доказательство.
- `GET /claims?q=...` ищет утверждения в локальной памяти и возвращает их ID (поиск по подстроке; не семантический).
- Журнал свидетельств: `POST /evidence` добавляет запись к существующему утверждению; `GET /evidence/<id>` показывает карту свидетельств. Записи добавляются отдельно, автоматического вердикта об истинности нет.

Пример `POST /evidence` (подставь существующий ID из `/memory` или другого ответа TRIAD):

```json
{
  "claim_id": 4,
  "relation": "supports",
  "evidence_type": "measurement",
  "statement": "Что именно наблюдалось или измерено",
  "source": "Прибор, документ или ссылка на исходные данные",
  "confidence": 0.7
}
```

Допустимые связи: `supports`, `weakens`, `qualifies`, `observes`. Типы: `observation`, `measurement`, `calculation`, `document`, `interpretation`, `other`. Проверки: `python test_triad.py`, `python test_science.py`, `python test_conflicts.py`.
- Локальная SQLite-память с типом записи, тегами, источником и уверенностью.
- Лексический поиск опорных записей.
- Безопасный ограниченный арифметический вычислитель.
- Три прохода: опора → вычисление/логика → проверка оговорок.
- Общая статистика трёх числовых входов.
- Размерностная проверка выражений по явно заданным размерностям.
- Поиск кандидатов на противоречие без автоматического удаления или перезаписи записей.

## Размерностный анализ
POST `/dimensions`:
```json
{
  "lhs": "F",
  "rhs": "kg*a",
  "symbols": {
    "F": {"M": 1, "L": 1, "T": -2},
    "kg": {"M": 1},
    "a": {"L": 1, "T": -2}
  }
}
```
Размерностная согласованность необходима, но не достаточна для доказательства физической правильности формулы. Размерности символов задаются явно.

## Проверка возможных противоречий
POST `/conflicts` с JSON `{"content":"утверждение для проверки"}` ищет похожие записи с возможным контрастом отрицания. Результаты — только кандидаты на ручную проверку; эвристика может ошибаться.
POST `/teach` сохраняет новую запись, не удаляя прежние, и возвращает найденные кандидаты. Политика хранения — append-only: обе версии остаются в памяти.

## Endpoints
- GET `/ping` — состояние движка и число записей.
- GET/POST `/ask` — вопрос или арифметическое выражение.
- POST `/teach` — добавить запись с источником и типом.
- GET `/memory` — статистика памяти.
- POST `/triad` — анализ трёх чисел.
- POST `/dimensions` — проверка размерностей.
- POST `/conflicts` — кандидаты на противоречия.
- POST `/evidence` — добавить свидетельство: `claim_id`, `relation`, `statement`, `source`; необязательно `evidence_type`, `confidence`.
- GET `/evidence/<claim_id>` — карта свидетельств; параметры `page` (по умолчанию 1) и `per_page` (по умолчанию 50, максимум 100). Счётчики связей показывают все свидетельства, список — только текущую страницу.

API слушает только `127.0.0.1:8002`; не выставлять наружу без аутентификации.

## Границы
Это не обученная языковая модель и не универсальный рассуждатель. Поиск памяти лексический, а эвристика противоречий не доказывает логическую несовместимость. Тройной вектор — статистика трёх чисел, а не доказательство физической гипотезы.
